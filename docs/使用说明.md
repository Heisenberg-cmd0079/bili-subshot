# 字幕长图 · 使用说明（2026-09 改造版）

## 〇、2026-09-28 新增：客户端链接直贴 + 标题自动命名

### 1. 网址栏可以直接粘贴客户端复制的整段内容

B 站客户端「复制链接」给的是这种带标题的格式：

```
【百K亚煞极电表神明，刷神明最快打法】https://www.bilibili.com/video/BV1aBhR69Ef6?vd_source=example
```

现在直接粘进「B 站视频网址」栏即可（Ctrl+V / 右键粘贴 / Shift+Insert 都行）：

* **自动拆标题**：`【…】`（也支持 `「…」`、`《…》`、`[…]`）里的文字会被取出来，
  填进「文件名前缀」；网址栏只留下干净的链接，不用再手动删标题。
* **自动清分享参数**：`vd_source`、`spm_id_from`、`share_source` 等跟踪参数会被删掉，
  但 `p=2`（分 P）、`t=` 这类有效参数保留。顺带的好处是：同一个视频不管从哪儿复制，
  链接都长一样，**下载缓存能复用**，不会重复下载一遍。
* **没有标题也能补**：粘贴的是纯链接 / `b23.tv` 短链时，程序会在后台调用
  B 站接口取回标题并填入；接口不通就只清链接，不影响使用。
  也可以随时点「从链接取标题」按钮手动取一次。
* 只粘 `BV1aBhR69Ef6` 这样的裸 BV 号也会自动补全成完整链接。
* **不跟用户抢方向盘**：如果「文件名前缀」是你自己敲的（不是自动填的），
  粘新链接时不会覆盖它；把前缀清空后，又会恢复自动跟随。

### 2. 文件名 = 标题 + 编号

「导出设置」里的「文件名」改名为**「文件名前缀」**，并新增 **「标题自动编号」** 开关（默认开）：

| 开关 | 输出文件名 |
| --- | --- |
| 标题自动编号 ☑（默认） | `百K亚煞极电表神明，刷神明最快打法_01.png`、`_02.png` … |
| 标题自动编号 ☐ | `百K亚煞极电表神明，刷神明最快打法.png`（同名会覆盖） |
| 再加「加时间戳」☑ | `百K亚煞极电表神明，刷神明最快打法_01_20260928_132353.png` |

编号规则：扫描导出文件夹里已有的「前缀_数字」文件，取**最大编号 +1**；
已存在的无编号旧图（例如 `黑赐.png`）不会被覆盖，新图从 `黑赐_01.png` 开始。
文件名里的 `\/:*?"<>|` 会自动换成 `_`，所以标题里带斜杠、问号也能安全落盘。

## 〇-A、2026-10-10 修复记录（标题自带括号时“被截断”）

**反馈现象**：粘贴客户端复制的整段内容（标题里自带一层副标题括号）

```
【示例：某视频的完整标题【第一话】】https://www.bilibili.com/video/BV1xx411c7mD?vd_source=…
```

之后，网址栏只剩一条短链接，「文件名前缀」也只填了内层的 **「第一话」**，
看起来像是「网址栏有字符上限、把长标题截掉了」。

**根因：标题正则不允许括号嵌套。** 旧版用

```python
re.compile(r"【\s*([^【】]{1,200}?)\s*】")
```

`[^【】]` 明确禁止内容里出现括号，而 B 站客户端的分享标题**自己就可能带一层括号**（副标题）。
于是第一个 `【` 永远配不上右括号，正则引擎退到内层那个 `【` 上匹配成功 —— 外层标题整段被丢掉。
（网址栏本身没有字符上限，链接和标题都完整读到了，丢字发生在解析环节。）

**修复：** 去掉这套标题正则，改成按字符下标做**括号配对、取最外层内容**（`subtitle_core.py`
里的 `_bracket_titles()`），支持任意层嵌套；`【】`、`「」`、`《》`、`[]` 四组括号统一走这套逻辑。

**顺带消除“看起来像被截断”的误会：**

* 网址栏下方新增一行小字，回显 **已识别标题：「…」→ 已填入「文件名前缀」** ——
  一眼能看出标题没丢，只是搬进了「文件名前缀」；
* 日志文案改为「已自动拆出标题「…」→ 文件名前缀；网址栏只留干净链接：…」；
* 顺手把 `config.json` 里被旧版写坏的前缀（内层括号里的「第一话」）改回完整标题。

**回归测试：** `tests_naming.py` 新增 5 条用例（嵌套一层 / 嵌套两层 / 右括号缺失 /
超长标题不吞链接 / GUI 粘贴后的前缀与回显），合计 32 项，全部通过：

```bat
python -X utf8 tests_naming.py
```

## 〇-B、2026-10-10 新增：应用图标（标题栏 / 任务栏 / 桌面快捷方式）

图标由生图插件 `gpt-image-2.5-flare` 生成（蓝底 + 三条白色字幕条 + 粉色播放键），
从 4 个候选方案里选了 A，落盘后加工成两份资源：

  脚本只把「与画布边缘相连的纯白背景」刷成透明，方块里的白色字幕条是封闭区域，不会被误伤。

* 桌面快捷方式 `B站视频台词拼接神器.lnk` 的图标一并指向 `assets\icon.ico`。


## 〇-C、2026-09-21 修复记录（字幕被截断 + 整段重复）

反馈现象（BV1nKTC6CEBq `00:20:57–00:21:53`，漫画画面）：
两行字幕只留下下面一行，同时同一句台词在长图里重复出现了好几次。

**根因有两个，都是“把白色像素当文字”造成的：**

1. **区域识别跑偏 → 截断。** 该片画面是漫画，白底黑线遍布全屏，
   旧版用「白色像素」当文字，于是把画面下半部分（y 485 ~ 1080，595px 高）
   整片判成“字幕行”。紧接着在抽帧里算裁切窗口时，
   `gy1`（分析区上界）按 50px 余量算出 435，而 `cy1`（裁切上界）是 259 ——
   `cy1 - gy1` 变成 **负数**，numpy 负索引会从数组**尾部**取数，
   结果每一条字幕条实际截的是**画面最底部 176px**，两行字幕的上面一行正好被切在窗口外。
2. **去重失效 → 重复。** 去重比较用的也是“白色像素掩码”，漫画背景的白色分格
   让同一句字幕在相邻帧之间 IoU 掉到 0.6 以下，一句被拆成好几组
   （实测同一句“漫画中的角色个个不同凡响且具有魅力”被拆成 6 组）。

**修复：**

* `text_mask()` 改用三重判据 —— **白字 ∩ 黑描边附近 ∩ 连通块尺寸像文字**
  （整片白底、色块、长条 UI 都会被第 3 条挡掉）。
  实测该片同一句字幕的 IoU 从 0.6 以下提升到 **0.73 ~ 0.79**，不同句只有 **0.04 ~ 0.10**。
* 区域识别改为统计**行存在率**（该行有多少帧出现字形），再**逐帧向上/下生长取并集**，
  因此“同一句分两行显示”时上面那行一定在范围内。
* 抽帧的分析区（`gy1/gy2`）改为按「字幕带 + 裁切范围」取，并在切片前把窗口
  夹在数组范围内 —— 从根上杜绝负索引。
* 分组时与「组内最近 3 帧」比较，且**短暂空窗（≤1s）不立即断组**，
  字幕闪烁、淡入淡出不会再拆出一堆重复。
* 兼容回退：若找不到稳定的“白字 + 黑描边”，改用不要求暗邻域的白字判据，**仍保留字形尺寸过滤**，并将同一策略用于两轮抽帧。手动区域也会选择描边策略。
* 亮背景和白字可能一起超过白色阈值并连成一片。无描边模式在字形过滤后为空时，会用局部亮度对比分离较亮的白字，再做相同过滤；纯白底不会因此整片通过。
* 这不保证识别所有字幕：低对比白字无描边、彩色字幕可能仍不支持。请先确认字幕确实出现在所选区间内；若样式不支持，换用白字黑边素材，反复框选同一区域无法改变字幕颜色或对比度。

**结果（同一时间段重新生成）：** `1920×4530`，**17 句**，两行字幕完整、零重复
（修复前：`1920×7844`，39 句，含 6 处重复 + 多处截断）。

## 一、这次改了什么

### 1. 修掉「有概率截断字幕」

旧版只拿**第一帧**做一次 Otsu 二值化，把「画面里所有亮像素所在的行」都当文字：

* 游戏/画面里的亮色 UI 一多，`text_bottom` 就被推到画面底部，接着又被
  `max_sub_h = 12% 画面高` 这条限制反向裁切 —— 于是裁切窗口整体下移，
  **字幕上部被切掉**（就是你截图里那种“字形只有一半”的效果）。
* 只按第一帧推断，后面每一句字幕都套同一个错误窗口。

新版改成**多帧统计 + 逐帧生长**：

| 判据 | 说明 |
| --- | --- |
| 白字 | 亮度高、饱和度低 |
| **黑描边** | 硬字幕的白字外面都描了一圈黑边；画面里的白底、亮块不满足 |
| **尺寸像字** | 字形连通块的高宽/面积/填充率要落在“文字”范围内，整片白底与色块被挡掉 |
| 行存在率 | 该行在采样帧里出现字形的帧占比（常驻字幕行接近 100%） |
| 行内容变化程度 | 字幕会换句、行内像素量随之起伏；常驻白色 UI 条 / 工具栏纹丝不动 → 评分时降权 |
| 位置先验 | 越靠画面底部的候选段权重略高 |

先用前四维挑出种子行段，再**逐帧从种子向上下生长**（允许跨过几行空隙、有幅度上限），
最后取所有帧的并集 —— 所以「字幕分两行」时上面那行也在，最后按字高自动加留白
（`文字带高 × 25%`），并用所有保留帧的真实文字边缘做兜底扩展。

> 实测过的坑：录屏类视频底部常带一条常驻的白色工具栏（截图工具条、播放器控件等），
> 它的行存在率能到 100%、比字幕“更像文字”。这类行**几乎不换内容**，
> 靠「行内容变化程度」这一维就会被大幅降权（实测字幕行变化率 ≈0.6，工具栏 ≈0）。

### 2. 修掉「重复台词 / 漏台词」

旧版比较的是**画面底部 25% 的灰度图**，游戏画面一动画相似度就掉到 0.85 以下，
同一句台词被当成两句（重复）；反之偶发相似又会漏句。

新版只比较**字幕字形掩码**（白字 + 黑描边 + 尺寸像字，见上）：

* 同句字幕：掩码 IoU 实测 0.73 ~ 0.79，包含度 0.85 ~ 0.91
* 不同台词：掩码 IoU 实测 ≤ 0.10，包含度 ≤ 0.20

阈值取 IoU 0.50、包含度 0.82，两边都留足余量；
分组时与该组**最近 3 帧**比较（容忍逐字出现与轻微抖动），
**字幕短暂消失不超过 1 秒也不断组**，事后再做一次「相邻组间空隙 ≤2.5s 且字形相同则合并」的兜底。
每组再挑选「字形像素最多」的那一帧，规避淡入淡出/半透明帧。

### 3. 新增功能

* **导出文件夹设置**：可填、可「浏览…」选择，自动记忆到 `config.json`
* **打开文件夹**按钮：一键在资源管理器打开导出目录
* **字幕区域预览 / 微调**：可视化窗口，红色半透明带就是会被保留的裁切范围，
  两个滑块可手动微调（默认「自动识别」已预填好结果，通常不用动）
* 首帧保留完整画面 / 字幕条分隔线 / 横向裁切到文字 / 完成后自动打开图片（开关）
* 文件名前缀 + 自动编号 / 可选时间戳后缀，避免覆盖旧图
* 网址栏粘贴客户端整段内容（【标题】+ 链接）自动拆标题、清分享参数（见第〇节）
* 浏览器 Cookies 选项（B 站 1080P 需要登录时选 Edge/Chrome 即可）
* 下载片段带缓存，重复生成不重新下载；「清理缓存」按钮一键清空
* 窗口自适应高 DPI（175% 缩放的小屏也能完整显示）
* 输出文件名、日志中的图标全部换成中文字体可正常显示的符号

### 4. 细节修正

* **首帧整图会裁掉字幕下方的空白/UI 区域**（字幕位于画面下部时）。
  否则首帧底部那条没字的画面看起来很像“多拼了一条空字幕”。
* 首帧整图与第一条字幕之间**同样画分隔线**，封面边界一目了然。
* 新增「非字幕画面」过滤：整块 UI 亮条（例如 `← ESC` 按钮条）没有字形连通块，
  或白像素量远低于台词水平的分组会被直接丢掉，不会再混进长图。
* **裁切窗口强制夹在分析区内**（越界时自动收敛并在日志里提示），
  杜绝“负索引从数组尾部取数”这类会把字幕切到画面最底部的问题。

   网址栏随后只会显示**干净链接**，识别到的完整标题在网址栏下方那行小字里回显，

2. 「导出设置」里选导出文件夹（点「打开文件夹」可直接跳过去）；
   文件名前缀默认就是视频标题，保持「标题自动编号」勾选，输出即 `标题_01.png`
3. 「字幕区域」保持默认的 **自动识别（推荐）** 即可；
   想确认效果就先点 **预览 / 微调字幕区域**
4. 点 **一键生成拼接图**，完成后自动打开图片

## 四、命令行

```bat
python -X utf8 bilibili_subtitle_stitcher.py ^
    --url "【某视频标题】https://www.bilibili.com/video/BV1qnuq6dEga?vd_source=xxx" ^
    --start 00:21:41 --end 00:22:35 ^
    --out "output"
```

常用参数：

| 参数 | 说明 |
| --- | --- |
| `--url` | 视频链接；也可直接粘贴「【标题】https://…」整段内容（标题会用作文件名） |
| `--out` | 导出文件夹 |
| `--name` | 输出文件名前缀（不带编号与扩展名），链接自带标题时以标题优先 |
| `--title` | 强制指定文件名前缀（优先级最高） |
| `--no-number` / `--number` | 关闭 / 开启自动编号（默认跟随配置，开启时输出 `前缀_01.png`） |
| `--cookies {无,Edge,Chrome,Firefox}` | 用浏览器 cookies 拉取更高码率 |
| `--region 80,92` | 手动指定字幕区域（占画面高度百分比），不填即自动识别 |
| `--no-cover` | 首帧不做完整画面 |
| `--no-separator` | 字幕条之间不加分隔线 |
| `--crop-horizontal` | 横向裁切到字幕文字范围（更紧凑） |
| `--keep-cache` | 结束后保留下载的临时视频 |

不带参数运行时读取 `config.json`（与界面同一份配置）。
临时视频缓存在 `%TEMP%\zimupinjie\<视频+时间段的哈希>\clip.mp4`。
